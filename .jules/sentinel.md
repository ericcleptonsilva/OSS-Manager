## 2024-05-18 - Over-fetching credentials from Parse Server
**Vulnerability:** Retrieving full database records for Team and Academy exposed plain-text `adminPassword` credentials directly to the client payload, allowing anyone monitoring network requests to steal admin privileges.
**Learning:** Parse Server queries return all properties by default. While stripping sensitive fields inside client-side JS mapping functions might seem secure, it is merely "security theater", as the full payload was already transmitted over the network and remains visible in dev tools. Additionally, when restricting queries for authentication, using server-side `.equalTo('adminPassword', pass)` must ALWAYS be paired with a unique identifier filter (like email) first. If a password filter is used alone, and the attacker inputs a common password, the server will leak all records that share that common password, worsening the exposure.
**Prevention:** ALWAYS apply `.exclude('adminPassword')` directly to `Parse.Query` instances on the server/SDK side before `.find()` or `.first()` is executed to ensure sensitive fields never traverse the network. In authentication flows, perform the unique identifier match on the client if necessary (e.g., case-insensitive email), but perform password verification securely on the server via `.equalTo()`.
