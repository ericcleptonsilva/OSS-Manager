## 2024-05-18 - Client-Side Auth Bypass & Credential Leak via Parse Queries
**Vulnerability:** The application was downloading entire `Team` and `Academy` objects, including `adminPassword` and `adminEmail` fields, to the client-side to perform custom login validation. It also failed to validate empty string credentials, potentially allowing an authentication bypass if both the stored password and user input were empty strings.
**Learning:** Returning full objects without projection/exclusion in public queries exposes all fields (including credentials) over the network. Furthermore, querying data to validate on the client-side is inherently insecure; validation should happen on the server-side via constrained queries.
**Prevention:** Always use `.exclude()` on Parse queries to hide sensitive fields in payloads sent to the client. Implement custom authentication logic using targeted server-side `.equalTo()` queries so credentials are not exposed to the client. Always pre-validate authentication inputs to ensure they are not empty strings before running queries.
