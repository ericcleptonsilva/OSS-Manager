## 2024-05-24 - Data Exposure Prevention via Parse Query Exclusion
**Vulnerability:** Sensitive fields like `adminPassword` and `adminEmail` on Parse Server `Team` and `Academy` objects were being retrieved by the frontend via `fetchFullData` and `fetchPublicData`, risking credential exposure over the network payload.
**Learning:** Removing sensitive fields only in client-side mapper functions is insufficient, as the raw data is already transmitted and accessible in the network tab. `Parse.Query.exclude()` must be used to block the fields from ever leaving the server. Also learned not to assume fields exist (like `adminEmail` on `Academy`) and to verify schema before patching.
**Prevention:** Apply a blacklist approach (`.exclude()`) directly on Parse queries to ensure sensitive credentials are never queried unless explicitly required for server-side validation. Always verify model fields via codebase grep or schema inspection before applying field-level query modifications.
