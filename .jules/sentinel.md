## 2024-05-24 - [Fix Admin Credential Exposure and Auth Logic]
**Vulnerability:** The application was exposing sensitive credentials (`adminEmail`, `adminPassword`) in public and full data queries by not explicitly excluding them. Furthermore, the custom authentication fallback (`performCustomLogin`) was fetching objects and performing credential comparison on the client-side, making it possible for attackers to bypass auth if they captured the payload, and failed to adequately check for empty strings before attempting comparison, risking bypasses if both sides were empty.
**Learning:** Client-side filtering (e.g., removing passwords in mappers) is insufficient because the raw payload is still sent over the network. Parse Server queries must use `.exclude()` to strip sensitive fields at the database level before transmission. Authentication logic must never scan tables and perform matching on the client-side; instead, it must use targeted server-side `.equalTo()` queries and strict input validation (e.g., ensuring inputs are not empty strings).
**Prevention:** Always use `.exclude()` on Parse queries for known sensitive fields. Ensure all authentication mechanisms rely on server-side validation and never fetch secrets to the client for comparison. Explicitly validate inputs to prevent edge cases like empty string matching.
