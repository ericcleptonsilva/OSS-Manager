## 2025-02-14 - Fix Data Exposure and Authentication Bypass via Credentials Sent to Client
**Vulnerability:** The application was fetching sensitive fields `adminPassword` and `adminEmail` from the `Team` and `Academy` collections during public and private data loading (`fetchFullData` and `fetchPublicData`) without excluding them on the server side. Furthermore, custom login fallbacks (`performCustomLogin`) were relying on pulling these credentials to the client for comparison, allowing auth bypass if empty strings were provided, and exposing all administrative credentials to any user via network intercept.
**Learning:** Parse queries must explicitly exclude sensitive fields on the server side (`query.exclude('field')`) instead of relying on client-side mapping functions that omit the field from the UI payload. Additionally, authentication should always occur via targeted server-side queries (`query.equalTo('password', input)`) rather than client-side comparisons.
**Prevention:** Apply `query.exclude()` on sensitive credential fields for any Parse queries sent to the client. Validate credentials for empty strings before performing queries to prevent matching unexpected backend empty values. Use `.equalTo()` constraints securely.
