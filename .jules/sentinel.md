## 2025-02-28 - Secure Client-Side Auth Fallback
**Vulnerability:** The application was vulnerable to Insecure Direct Object Reference and Credential Exposure during the custom login fallback (`performCustomLogin`). When standard login failed, the frontend requested the entire `Team` and `Academy` objects from Parse (including the plaintext `adminPassword`), bringing them to the client to perform a local string comparison against the user's input password.
**Learning:** Sending raw passwords to the client-side for validation completely compromises the credentials, making them visible in network developer tools regardless of whether the user is successfully authenticated.
**Prevention:** Always push filtering logic to the database engine. Use server-side queries (e.g., `equalTo('adminPassword', inputPass)`) to locate matching records, and aggressively apply `.exclude('adminPassword')` on all general data-fetching endpoints (`fetchFullData`, `fetchPublicData`) to ensure sensitive fields never traverse the network.
