## 2024-05-24 - Parse Server Server-Side Validation Limitations with Case-Sensitive Matching
**Vulnerability:** Fetching complete database objects directly to the client exposes sensitive fields like plaintext passwords (`adminPassword`) when objects like `Team` or `Academy` are mapped to client objects.
**Learning:** While using `query.exclude('adminPassword')` correctly stops the password from hitting the network, and `query.equalTo('adminPassword', pass)` pushes authentication to the server, Parse Server strictly performs case-sensitive matching for `.equalTo()`. This breaks when an identifier (like `adminEmail`) needs case-insensitive matching. Thus, you CANNOT exclude an identifier field if you intend to fetch candidates and filter them client-side based on case-insensitive rules.
**Prevention:** Always push password evaluation to the database level with `equalTo` and use `.exclude()` to prevent it from crossing the wire. However, explicitly handle case-insensitive fields by fetching them to the client to do local trimming/case-normalization (`.toLowerCase()`), ensuring you do NOT apply `.exclude()` to fields required for local memory processing.
